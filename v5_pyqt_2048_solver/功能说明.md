# 第 5 版 · 算法求解版 功能说明

> 目录：`v5_pyqt_2048_solver/`
> 入口：`v5_pyqt_2048_solver.py`（可运行）｜算法核心：`solver_2048.py`｜测试：`test_solver.py`
> 配套博客：《第 5 篇：经典算法求解 2048》

第 5 版在**第 4 版图形界面（动画版）基础之上做增量扩展**：原有布局、交互逻辑、视觉风格与操作流程保持不变，仅在游戏页新增一块「AI 求解」面板与一个「AI 求解」入口按钮，用于把经典求解算法接入现有界面。

---

## 1. 设计原则

1. **界面零回归**：直接复用第 4 版的 `MainWindow` / `BoardView` / `ParticleOverlay` / `AnimatedGameCore` 与全部视觉常量，v5 只做子类化扩展，不修改第 4 版任何一行代码。
2. **像素级兼容 + 屏幕自适应**：
   - 启动页尺寸与第 4 版完全一致（客户区 500×672）；
   - 进入**游戏页**时窗口向下加高承载求解面板，但高度**自适应屏幕**：
     `目标高度 = clamp(886, 下限, 屏幕可用高度 − 标题栏预留)`，且不低于"游戏页布局最小高度"；
   - 屏幕不够高时，求解面板自动变矮并**转为面板内部滚动**（策略/按钮/状态/日志始终可访问）；
   - **启动时窗口自动居中**于屏幕可用区域；进入游戏页后若被系统摆到屏幕外（高缩放下常见：标题栏被顶到屏幕上方而抓不到、拖不动），会自动校正回可见区域，保证标题栏始终可抓取；
   - 一旦用户手动拖动过窗口，之后**只做越界校正、不再强制居中**，不打扰用户摆放。
   - 因此：启动页仍与第 4 版逐像素一致；游戏页上方原有控件坐标完全不变，面板追加在按钮行下方。
3. **求解与界面解耦**：`solver_2048.py` 是纯逻辑模块（只对 4×4 网格做运算），不依赖 PyQt，可单独运行与测试。
4. **不阻塞、不崩溃**：求解在后台线程执行，带时间预算与异常兜底；即使求解出错，界面与原有功能照常可用。

```bash
# 启动第 5 版（算法求解版）
python v5_pyqt_2048_solver/v5_pyqt_2048_solver.py
```

## 5. 算法说明

### 5.1 棋盘机制

与第 3/4 版 `GameCore` 规则完全一致：一次移动中每个方块最多参与一次合并（`[2,2,2,2] → [4,4]`）。核心函数：`slide_line` / `move_grid` / `is_game_over` / `legal_moves`。

### 5.2 启发式评估（`evaluate`）

综合打分 `权重 · 特征`：

| 特征 | 含义 | 默认权重 |
| --- | --- | --- |
| `empty` | 空格数量 | 2.7 |
| `monotonicity` | 行/列单调性（越接近 0 越好） | 1.0 |
| `smoothness` | 相邻块 log2 差值（越平滑越好，取负） | 0.10 |
| `merge` | 相邻可合并对数（合并潜力） | 1.0 |
| `corner` | 最大块在四角时奖励 `log2(最大值)` | 0.30 |
| `snake` | 蛇形路径权重位（大块靠前越集中越好，Phase E 新增，可选） | 0.0（默认关闭） |
| `danger` | 危险度惩罚（空格过少 / 大块被困，Phase E 新增，可选） | 0.0（默认关闭） |

- `empty / monotonicity / smoothness / merge / corner` 为基线特征；`snake / danger` 为 **Phase E 新增的可选特征**，默认权重为 0（不改变既有行为），可通过 `DEFAULT_WEIGHTS` 调整开启（消融见 `experiments/ablation.py` 的 `suite_heuristic`）。
- `evaluate_features()` 可输出各分项，便于解释「为什么这么走」。

### 5.3 五类策略（对应《第 5 篇》的讲解顺序）

| # | 策略（key） | 说明 | 强度参数 | 代价 |
| --- | --- | --- | --- | --- |
| 1 | 启发式（`heuristic`） | **规则 / 启发式**：对 4 个方向各做一次移动，取评估值最高者（monotonicity / smoothness / max-in-corner…） | 无 | < 1ms |
| 2 | 贪心模拟（`rollout`） | **lookahead with rollout**：每个方向做 N 次随机模拟（随机走子到深度上限），取平均收益 | rollout 次数 / 截断深度 | 低 |
| 3 | Expectimax（`expectimax`） | **带期望的 minimax**：对随机新方块（90% 出 2 / 10% 出 4）做期望分支 + 迭代加深 | 深度 / 时间预算 / 剪枝 | 中 |
| 4 | MCTS（`mcts`） | **蒙特卡洛树搜索**：UCT 选择 + 渐进加宽 + rollout 截断，长期规划 | 模拟次数 / 时间预算 | 中 |
| 5 | 强化学习（`rl`） | **on-policy 策略梯度（REINFORCE + 价值基线 + 熵正则）**，MLP `256→128→{策略,价值}`，模型见 `rl_model.npz`；训练按 masked-softmax 分布采样，推理用 masked argmax | 无 | 极快（一次前向） |

- 强度下拉框（快速 / 标准 / 强力）仅对 1 中带参数的 2/3/4 生效，其余自动置灰。
- 对外接口：`solve(grid, strategy=..., **params)`、`build_config(strategy, preset)`、`describe_config(config)`。
- **可复现性（如实区分）**：由“次数/深度”约束的配置（启发式 / 贪心模拟 / 强化学习，以及显式固定次数的 MCTS、关闭时间预算的 Expectimax）在固定种子下可逐位复现；一旦加入**墙钟时间预算**，其完成深度/模拟次数取决于机器负载，因此**不保证逐位复现**（只保证同参数同机器下结果稳定可用）。

### 5.4 剪枝与近似（Phase B/C 修正后）

**Expectimax（严格区分“精确”与“近似”）**

| 机制 | 分类 | 做法 |
| --- | --- | --- |
| `prune=False` | **精确（无损）** | 穷举全部合法动作 × 全部空位 × {2,4}，机会节点取 `(1/E)·Σ[0.9·V(生成2)+0.1·V(生成4)]`；与独立参考实现逐位一致（测试容差 1e-9） |
| 转置表 TT | **无损**（可单开关） | 键含 `(盘面, 剩余深度, 节点类型)`；**若启用概率截断则额外含精确路径概率 p**（不做近似舍入，避免不同 p 被误判为同一上下文而错误复用） |
| 空位采样 `sample_limit` | 近似 | 空位 > 上限时用**无放回均匀子样**的均值作为期望估计（无偏、有方差；固定种子可复现） |
| 概率截断 `prob_cutoff` | 近似 | 分支概率 `p·(1/E)·p_value` 低于阈值时**不再展开**，直接用启发式近似其子价值；**概率权重 0.9/0.1 与 1/E 完整保留**（不丢概率质量、不用错误分母归一化） |
| 移动排序 `move_order` | 仅次序启发 | 时间预算下优先探索启发式估值高的方向；**不改变完全搜索结果**，也不是“无损降低复杂度” |

- 路径概率修正：`p_child = p · (1/E) · p_value`，**不会在 MAX 节点被重置为 1**（修正 E01）。
- 根节点口径统一（V5.1/H1 修复）：根节点与内部 MAX 节点一致地计入 `score_weight · 本步合并分`，此前根节点漏记该分（在根处存在合并的盘面上会与精确参考不一致）。
- 超时保护：**超时导致的未完成子树不写入 TT**（修正 E02）；TT 为单次调用内的局部结构。
- 统计口径：`nodes / leaf_evals / cache_hits / cutoffs / sampled_chance / chance_nodes / elapsed_ms / depth_reached / timed_out`。

**MCTS（Phase C 修正 + V5.1/H1 回传与加宽修复）**

- 节点显式区分 `PLAYER` / `CHANCE`；**先移动（得合并分）→ 再由机会节点按真实分布生成新块 → 进入下一玩家节点**。
- 机会节点**每次按真实转移分布采样**（空位 1/E、2/4 = 0.9/0.1，与游戏主体同一函数 `sample_spawn`），并以“结果局面”为 key 复用同状态子节点——**不再“先随机取 K 个再从缓存里均匀选”**（修正 M01/M02）。
- 统一回报口径：`根→叶累计合并分 + 截断处启发式`，所有候选动作同尺度回传（修正 M03）。
- **搜索路径与回传不变量（H1 修复）**：`descend()` 显式维护 root→leaf 路径；触发宽度上限时**不再构造无 parent 的临时节点**（旧实现会导致该 simulation 计入了 completed 却未累加到 root），而是对真实采样局面 rollout 后沿路径回传。不变量：`root_visits == completed_simulations == backpropagated_simulations`，且根各合法动作访问次数之和 == `root_visits`（由 100/500/1000 模拟 × 宽度 1/2/4/8/16/32 的测试验证）。新增统计字段 `completed_simulations / backpropagated_simulations / root_visits / root_move_visits / width_limit_rollouts`。
- **渐进加宽（H1 新增，可选）**：`progressive_widening=True` 时机会节点宽度上限为 `K(N)=min(Kmax, max(1, ceil(cpw·N^alpha)))`（N 为该机会节点访问次数，N=0 时 K=1）；只在“是否新增子节点”上生效，**不改变真实 spawn 采样分布**（已由分布统计测试验证 p(2)≈0.9）。默认仍为固定宽度 `max_chance_width`（保持既有默认行为）。
- 参数 `c`（UCT 探索常数）、`simulations`、`max_chance_width`、`cpw / alpha` 均可消融。

### 5.5 强化学习（`rl_2048.py`，Phase D 修正）

- 特征：`4×4×16` one-hot（通道 k = 该格指数，k=0 为空格）→ 256 维；网络 `256 → 128 → {策略 logits(4), 价值 V(1)}`（共享隐藏层），纯 numpy。
- 算法类型：**on-policy 策略梯度（REINFORCE + 价值基线 + 熵正则）**。训练**按 masked-softmax 分布抽样**（行为策略 = 策略梯度所用分布，无 off-policy 偏差；已移除 ε-greedy 混合），推理用 masked argmax。
- 梯度修正（已用中心有限差分逐参数验证，最大相对偏差 ≈ 3e-8）：
  - 价值头 `dL/dWv = (V-G)·h`（此前符号相反，会让价值朝误差增大方向更新）；
  - 共享隐藏层 `dL/dh = W2ᵀ·dlogits + (V-G)·Wvᵀ`（此前漏掉价值头回传）；
  - 优势按 stop-gradient 处理；回报归一化 + ±5 截断 + 全局梯度裁剪 5.0 + 非有限值跳过。
- 训练管理（V5.1/H2 增强）：`--eval-every` 验证集周期评估、**best/latest/candidate 三类检查点**（原子写）、`--patience` 早停；`--init`（从指定模型初始化权重）与 `--resume`（**warm start**：优先读取 `--out` 的 `.latest.npz` 检查点，仅恢复**权重与元数据**，**不**恢复 Python/NumPy RNG 与优化器状态，因此**非精确断点续训**，不承诺逐局一致复现）语义区分；每局记录 `episode_len / grad_norm / entropy / value_mse / grad_clip_ratio` 训练诊断。
- **三个随机数家族隔离（H2）**：训练 `--seed`、验证 `--eval-seed`（仅用于 best 选择）、独立门禁 `--holdout-seed`（仅用于新旧模型替换判据）三者必须互不相同（CLI 强制校验）。
- **独立 holdout 门禁（H2）**：候选先原子写入 `rl_model.candidate.npz`；在**同一批独立 holdout 环境种子**上配对比较新旧模型，输出配对差值与 bootstrap 95% CI，**仅当差值 CI 下界 > 0（显著更优）才原子替换** `rl_model.npz`，否则**保持现有正式模型、不强行部署**；替换前做版本化备份（`rl_model.npz.bak.<时间戳>.npz`），支持回滚。
- **模型校验与旧版兼容（H2）**：加载时校验 `_schema`、权重 shape、dtype、NaN/Inf；旧版（V1，无 `_schema`）模型走**专用兼容加载路径** `load_legacy_model()`，严格加载会明确拒绝。
- 明确**不引入 DQN 经验回放**：on-policy 算法引入回放需 off-policy 校正或更换范式，不属于本实现范围。

```bash
python v5_pyqt_2048_solver/rl_2048.py --games 8000 --eval-every 1000 --patience 3   # 训练（含独立 holdout 门禁）
python v5_pyqt_2048_solver/rl_2048.py --eval-only                                   # 仅评估
python v5_pyqt_2048_solver/rl_2048.py --games 8000 --init v5_pyqt_2048_solver/rl_model.npz  # 从指定模型初始化
python v5_pyqt_2048_solver/rl_2048.py --games 2000 --resume                        # warm start 续训（读 .latest.npz；仅恢复权重/元数据，非精确断点续训）
# 三个随机数家族必须互不相同：--seed（训练）/ --eval-seed（验证）/ --holdout-seed（门禁）
```

> **RL 推理热路径（H2.9）**：求解时不再每步重新读取 `.npz`；以“规范化绝对路径 + 文件身份 `(size, mtime_ns)`”为键缓存模型，模型被原子替换后自动失效重载（`solver_2048._load_rl_model_cached`）。缓存只消除重复磁盘读，**不**据此宣称全链路加速比。

> 本仓库 `rl_model.npz` 为 Phase D 修正后、对旧模型增量训练 8000 局所得的 **best 检查点**：在固定验证集（50 局，seed=12345，贪心）上 **平均分 2267.4 / 最高分 6780 / 最大瓦片 512**，同口径下旧模型为 1445.7（**+57%**）。
> **V5.1 说明**：本次算法与工程收口**未重训、未替换正式模型**——`rl_model.npz` 哈希保持不变；门禁改为更保守的独立 holdout 配对判据（新模型需在 CI 上显著更优才会部署，否则保持现状）。
> **能力边界（如实说明）**：仍是**无经验回放、无超参自适应**的 on-policy 实现；作为参照，纯随机走子平均分 ≈ 1170–1200（最大瓦片 ≤256）。要显著变强需补齐回放/自适应超参或更大网络与更多自对弈。
> 若未训练模型，选择「强化学习」会在面板提示未找到模型（不影响其它策略）。

### 5.6 复杂度与性能（本机实测）

| 场景 | 参数 | 节点/模拟数 | 单步耗时 |
| --- | --- | --- | --- |
| 启发式 | — | 4 | < 1ms |
| 贪心模拟 · 标准 | rollout×20，深度 16 | 40 次 rollout | 约 40–60ms |
| Expectimax · 标准（含剪枝） | 深度 4，0.30s | 数百（TT 命中明显减少） | 约 25–60ms |

| 强化学习 | 一次前向 | — | < 1ms |

## 7. 稳定性与性能保障

| 风险 | 处理 |
| --- | --- |
| 搜索耗时导致界面卡顿 | 求解在 `QThread`（`SolverWorker`）后台执行，主线程只负责动画与刷新 |
| 搜索爆炸 / 卡死 | 时间预算 + 迭代加深 + 硬上限，超时回退到已完成深度 |
| 求解抛异常 | `solve()` 内部 `try/except` 兜底返回可用结果；工作线程异常经 `failed` 信号上报，界面仅提示并停止求解，**不影响原有功能** |
| 线程生命周期 | 工作线程按需创建、空闲即回收；交互「停止」做**短等待**（`SOLVER_STOP_WAIT_MS=500`）以免阻塞主线程，未退出的线程转入**退休列表**保留引用、待 `finished` 后回收；关闭窗口时对“当前 + 全部退休线程”做**有界等待**（`SOLVER_CLOSE_WAIT_MS=3500`）；**全程不使用 `QThread.terminate()`** |
| 过期结果污染新任务 | 结果/失败信号**先校验**（任务在运行 → `job_id` 匹配 → 棋盘快照未变）**后**才更新 `_solve_in_flight`/进度/会话；协作式取消（`threading.Event`）+ 有界预算（不宣称“即时中断”） |
| 用户与 AI 操作冲突 | 求解运行期间屏蔽手动移动 / 撤销 / 重做（沿用第 4 版"动画中忽略输入"的保护思路） |
| 高 DPI（125%/150%） | 只承诺**可用性**（文字不裁切、窗口落进屏幕、控件不重叠，基于 Qt `AA_EnableHighDpiScaling` + 窗口高度自适应）；**不做逐 DPI 像素级打磨**（决策见 `experiments/v5_1/known_issues.md` §D） |
| 会话历史损坏 | `solver_results/sessions.json` 采用**原子保存**（临时文件 + fsync → 旧文件转存 `.bak` → 同盘替换），写入中断不产生半截 JSON，损坏时可从 `.bak` 回滚读取 |
| 存档污染 | v5 使用独立 `game_history/` 与 `solver_results/`，与第 4 版互不干扰 |
