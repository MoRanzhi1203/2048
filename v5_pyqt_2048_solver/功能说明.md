# 第 5 版 · 算法求解版 功能说明

> 目录：`v5_pyqt_2048_solver/`
> 入口：`v5_pyqt_2048_solver.py`（可运行）｜算法核心：`solver_2048.py`｜测试：`test_solver.py`
> 配套博客：《第 6 篇：经典算法求解 2048》

第 5 版在**第 4 版图形界面（动画版）基础之上做增量扩展**：原有布局、交互逻辑、视觉风格与操作流程保持不变，仅在游戏页新增一块「算法求解」面板与一个「AI 求解」入口按钮，用于把经典求解算法接入现有界面。

---

## 1. 设计原则

1. **界面零回归**：直接复用第 4 版的 `MainWindow` / `BoardView` / `ParticleOverlay` / `AnimatedGameCore` 与全部视觉常量，v5 只做子类化扩展，不修改第 4 版任何一行代码。
2. **像素级兼容 + 屏幕自适应**：
   - 启动页尺寸与第 4 版完全一致（客户区 500×672）；
   - 进入**游戏页**时窗口向下加高承载求解面板，但高度**自适应屏幕**：
     `目标高度 = clamp(886, 下限, 屏幕可用高度 − 标题栏预留)`，且不低于"游戏页布局最小高度"；
   - 屏幕不够高时，求解面板自动变矮并**转为面板内部滚动**（策略/按钮/状态/日志始终可访问）；
   - **启动时窗口自动居中**于屏幕可用区域；进入游戏页后若被系统摆到屏幕外（高缩放下常见：标题栏被顶到屏幕上方而抓不到、拖不动），会自动校正回可见区域，保证标题栏始终可抓取；
   - 一旦用户手动拖动过窗口，之后**只做越界校正、不再强制居中**，不打扰用户摆放。
   - 因此：启动页仍与第 4 版逐像素一致；游戏页上方原有控件坐标完全不变，面板追加在按钮行下方。
3. **求解与界面解耦**：`solver_2048.py` 是纯逻辑模块（只对 4×4 网格做运算），不依赖 PyQt，可单独运行与测试。
4. **不阻塞、不崩溃**：求解在后台线程执行，带时间预算与异常兜底；即使求解出错，界面与原有功能照常可用。

## 5. 算法说明

### 5.1 棋盘机制

与第 3/4 版 `GameCore` 规则完全一致：一次移动中每个方块最多参与一次合并（`[2,2,2,2] → [4,4]`）。核心函数：`slide_line` / `move_grid` / `is_game_over` / `legal_moves`。

### 5.2 启发式评估（`evaluate`）

综合打分 `权重 · 特征`：

| 特征 | 含义 | 默认权重 |
| --- | --- | --- |
| `empty` | 空格数量 | 2.7 |
| `monotonicity` | 行/列单调性（越接近 0 越好） | 1.0 |
| `smoothness` | 相邻块 log2 差值（越平滑越好，取负） | 0.10 |
| `merge` | 相邻可合并对数（合并潜力） | 1.0 |
| `corner` | 最大块在四角时奖励 `log2(最大值)` | 0.30 |

`evaluate_features()` 可输出各分项，便于解释「为什么这么走」。

### 5.3 五类策略（对应《第 6 篇》的讲解顺序）

| # | 策略（key） | 说明 | 强度参数 | 代价 |
| --- | --- | --- | --- | --- |
| 1 | 启发式（`heuristic`） | **规则 / 启发式**：对 4 个方向各做一次移动，取评估值最高者（monotonicity / smoothness / max-in-corner…） | 无 | < 1ms |
| 2 | 贪心模拟（`rollout`） | **lookahead with rollout**：每个方向做 N 次随机模拟（随机走子到深度上限），取平均收益 | rollout 次数 / 截断深度 | 低 |
| 3 | Expectimax（`expectimax`） | **带期望的 minimax**：对随机新方块（90% 出 2 / 10% 出 4）做期望分支 + 迭代加深 | 深度 / 时间预算 / 剪枝 | 中 |
| 4 | MCTS（`mcts`） | **蒙特卡洛树搜索**：UCT 选择 + 渐进加宽 + rollout 截断，长期规划 | 模拟次数 / 时间预算 | 中 |
| 5 | 强化学习（`rl`） | **策略/价值网络（MLP）+ 自对弈策略梯度**，模型见 `rl_model.npz` | 无 | 极快（一次前向） |

- 强度下拉框（快速 / 标准 / 强力）仅对 1 中带参数的 2/3/4 生效，其余自动置灰。
- 单次决策一律**确定性**：内部随机使用固定种子，同局面同参数结果一致，便于复现与测试。
- 对外接口：`solve(grid, strategy=..., **params)`、`build_config(strategy, preset)`、`describe_config(config)`。

### 5.4 剪枝思路（Expectimax）

| 剪枝 | 做法 | 作用 |
| --- | --- | --- |
| **转置表（TT）** | 以 `(盘面, 剩余深度, 节点类型)` 为键缓存估值 | 相同局面只算一次，去重收益最大 |
| **空位采样** | 空位 > `sample_limit` 时，按固定种子只取这些位置展开 | 分支从 `2E` 降到 `2·sample_limit`，抑制指数爆炸 |
| **累积概率截断** | 路径累积概率 < `prob_cutoff` 的深层子树，直接用启发式估值外推 | 剪掉极低概率的深层分支 |
| **移动排序** | max 节点先探索启发式估值高的方向 | 配合时间预算尽早得到好结果 |

默认参数：`sample_limit=8`、`prob_cutoff=0.08`、`use_tt=True`、`move_order=True`（见 `PRUNE_DEFAULTS`）。
MCTS 侧的“剪枝”体现为 **渐进加宽（chance 子节点上限）+ rollout 截断（深度上限）+ 模拟/时间双预算**。

### 5.5 强化学习（`rl_2048.py`）

- 特征：`4×4×16` 的 one-hot（通道 k = 该格指数为 k，k=0 为空格）→ 256 维；
- 网络：`256 → 128 → {策略 logits(4), 价值 v(1)}`，纯 numpy；
- 训练：自对弈 **REINFORCE + 价值基线 + 熵正则**（ε-greedy 探索、回报归一化与截断、全局梯度裁剪，保证数值稳定）；
- 使用：

```bash
python v5_pyqt_2048_solver/rl_2048.py --games 9000 --out v5_pyqt_2048_solver/rl_model.npz
python v5_pyqt_2048_solver/rl_2048.py --eval-only            # 评估平均分/最高分/最大瓦片
python v5_pyqt_2048_solver/rl_2048.py --games 9000 --init v5_pyqt_2048_solver/rl_model.npz  # 增量训练
```

> 若未训练模型，选择「强化学习」会在面板提示未找到模型（不影响其它策略）。本仓库附带的 `rl_model.npz` 为上述流程训练所得的演示模型：自对弈约 **18000 局**后，贪心评估 **平均分 ≈ 1370、最高分 ≈ 4800、最大瓦片 512**（教学演示级；要更强可继续 `--init` 增量训练或加大网络/轮数）。

### 5.6 复杂度与性能（本机实测，100% DPI）

| 场景 | 参数 | 节点/模拟数 | 单步耗时 |
| --- | --- | --- | --- |
| 启发式 | — | 4 | < 1ms |
| 贪心模拟 · 标准 | rollout×20，深度 16 | 40 次 rollout | 约 40–60ms |
| Expectimax · 标准（含剪枝） | 深度 4，0.30s | 数百（TT 命中明显减少） | 约 25–60ms |
| MCTS · 标准 | 200 次模拟 | 200 | 约 200ms（≤0.3s 预算） |
| 强化学习 | 一次前向 | — | < 1ms |

> 分支随深度指数增长，因此统一用「时间预算 + 迭代加深（或模拟次数上限）+ 剪枝」把不确定性控制在预算内。

## 6. 实时状态与结果输出

- **实时状态**：状态机 `就绪 / 求解中 / 运行中 / 已结束`，配合进度条忙态与状态行文本，逐步刷新。
- **中间结果**：步骤日志逐条追加（方向、评估分、分数、最大瓦片、耗时、超时标记）。
- **结构化结果**：每个求解会话（`SolveSession`）包含：

```json
{
  "id": "20261010_224221_330104",
  "strategy": "expectimax", "strategy_name": "Expectimax",
  "depth_label": "标准", "time_limit": 0.3,
  "mode": "auto", "mode_name": "自动连走",
  "started_at": "2026-10-10T22:42:21",
  "elapsed_ms": 2490.0, "timeout_count": 0,
```

## 7. 稳定性与性能保障

| 风险 | 处理 |
| --- | --- |
| 搜索耗时导致界面卡顿 | 求解在 `QThread`（`SolverWorker`）后台执行，主线程只负责动画与刷新 |
| 搜索爆炸 / 卡死 | 时间预算 + 迭代加深 + 硬上限，超时回退到已完成深度 |
| 求解抛异常 | `solve()` 内部 `try/except` 兜底返回可用结果；工作线程异常经 `failed` 信号上报，界面仅提示并停止求解，**不影响原有功能** |
| 线程生命周期 | 工作线程按需创建、空闲即回收；窗口关闭时确保 `quit()+wait()`，避免残留运行中的 `QThread` |
| 用户与 AI 操作冲突 | 求解运行期间屏蔽手动移动 / 撤销 / 重做（沿用第 4 版"动画中忽略输入"的保护思路） |
| 高 DPI（125%/150%）下整窗超出屏幕 | 窗口高度自适应屏幕 + 面板内部滚动兜底 + 进入游戏页时自动把窗口校正回可见区域，保证标题栏始终可抓取（可拖动） |
| 存档污染 | v5 使用独立 `game_history/` 与 `solver_results/`，与第 4 版互不干扰 |
