## 1) 棋盘与基本逻辑（Python 控制台版 — 简洁示例）

```python
# board.py
import random
from copy import deepcopy

class Board:
    def __init__(self, size=4, seed=None):
        self.size = size
        self.grid = [[0]*size for _ in range(size)]
        if seed is not None:
            random.seed(seed)
        self.score = 0
        self.add_random()
        self.add_random()

    def add_random(self):
        empties = [(r,c) for r in range(self.size) for c in range(self.size) if self.grid[r][c]==0]
        if not empties: return
        r,c = random.choice(empties)
        self.grid[r][c] = 4 if random.random() < 0.1 else 2

    def _compress_line(self, line):
        new_line = [v for v in line if v!=0]
        merged = []
        i = 0
        while i < len(new_line):
            if i+1 < len(new_line) and new_line[i] == new_line[i+1]:
                merged.append(new_line[i]*2)
                self.score += new_line[i]*2
                i += 2
            else:
                merged.append(new_line[i])
                i += 1
        merged += [0] * (self.size - len(merged))
        return merged

    def move_left(self):
        moved = False
        for r in range(self.size):
            old = self.grid[r][:]
            self.grid[r] = self._compress_line(old)
            if self.grid[r] != old:
                moved = True
        if moved:
            self.add_random()
        return moved

    # 其它方向利用转置或翻转实现
    def move(self, direction):
        # direction in {'up','down','left','right'}
        rotated = False
        if direction == 'up':
            self.transpose()
            rotated = True
            moved = self.move_left()
            self.transpose()
            return moved
        if direction == 'down':
            self.transpose()
            self.reverse_rows()
            moved = self.move_left()
            self.reverse_rows()
            self.transpose()
            return moved
        if direction == 'right':
            self.reverse_rows()
            moved = self.move_left()
            self.reverse_rows()
            return moved
        if direction == 'left':
            return self.move_left()

    def transpose(self):
        self.grid = [list(row) for row in zip(*self.grid)]

    def reverse_rows(self):
        self.grid = [list(reversed(r)) for r in self.grid]

    def is_game_over(self):
        # 还有空位或可合并则没结束
        for r in range(self.size):
            for c in range(self.size):
                if self.grid[r][c] == 0: return False
                if c+1 < self.size and self.grid[r][c] == self.grid[r][c+1]: return False
                if r+1 < self.size and self.grid[r][c] == self.grid[r+1][c]: return False
        return True

    def __repr__(self):
        return '\n'.join(['\t'.join(map(str,row)) for row in self.grid]) + f"\nScore: {self.score}"
```

## 4) 动画与性能优化（第 4 篇）

- 分两层渲染：静态背景格子（缓存为 pixmap） + 动画层（移动的 tile）减少重绘。
- 使用 GPU 加速（Qt 快速渲染）或减少重绘区域（只更新移动的方块矩形）。
- 动画实现：记录每个 tile 的起始像素位置与目标位置，用定时器插值（线性 / ease-in-out），每帧只重绘这些矩形。避免每帧重新布局逻辑。
- 动画帧率：目标 30–60 FPS，复杂效果与性能要权衡。

两种思路：

- 本地双人：两人交替操作或并行显示两个棋盘（共享随机种子 / 竞赛模式）。

## 6) 算法求解 2048（第 6 篇，重点篇）

常见算法按照难度与效果排序（博客内容可分小节讲解）：

1. 规则/启发式策略（monotonicity、smoothness、max-in-corner）— 简单且解释性强。
2. 贪心模拟 / 随机模拟（lookahead with rollout）— 低成本。
3. Expectimax（带期望的 minimax）— 对随机出现的新 tile 做期望分支，效果好但计算量大。
4. Monte Carlo Tree Search（MCTS）— 可以用于长期规划，需合适的 rollout /扩展策略。
5. 强化学习（DQN、Policy Gradient / AlphaZero-like）— 训练自动玩家，需大量自对弈或人类数据。

给出 Expectimax 伪代码 + 剪枝思路（depth 3-4 常见），并演示如何把评估函数设计为 `权重·(单元特征)`（比如空格数、合并潜力、平滑度、最大瓦片位置）。

## 7) 用历史数据训练（第 7 篇，最前沿也最工程化）

### 数据

- 每条记录包含：状态（board）、动作、下一状态、reward（得分差）、game_over。
- 格式：ndjson 或 SQLite；用于 RL 的经验回放最好保存为 (s,a,r,s',done)。

### 特征表示

- 原始数值 -> 建议用 `log2(tile_value)` 或 one-hot 分层编码（16/12 维），因为 tile 值指数增长。
- 常见做法：把 4x4 看成 4x4xK 的张量（K = possible exponents），或直接归一化后用 CNN/MLP。

### 模型结构建议

- 小型取向（能在 CPU/GPU 上训练）：卷积网络或 MLP，输入 4x4xK，输出动作概率（策略）和/或价值估计（单值）。
- 大型“模型”思路：Transformer 或 ResNet-like 结构（对棋盘大小不是很大，但如果你想做“大模型”，可以尝试更深的网络，并结合自对弈数据）。

### 训练流程（两条主线）

A. 监督学习（imitation learning）

- 从人类历史数据拟合策略：训练分类器 `π(a|s)`，评估指标：准确率/平均分。优点：收敛快；缺点：受限于数据质量。

B. 强化学习（self-play / on-policy/off-policy）

- DQN：离线/在线经验回放，Q(s,a) 学习；需要奖励设计（即时得分或稀疏奖励）。
- Policy Gradient / PPO：直接学习策略，稳定性较好。
- Self-play loop：模型对弈生成新数据 -> 加入数据池 -> 继续训练 -> 评估。

### 评估指标

- 平均分、最大瓦片（2048/4096/8192）、达到 2048 的比例、胜率（如果双人/对手存在）、训练曲线稳定性。

### 工程化细节

- 保存 checkpoints、tensorboard 可视化、随机种子记录、复现实验日志（wandb 可选）。
- 计算资源：初期用单 GPU（消费级）可行；若做“大模型”或超大数据集，考虑多 GPU/TPU。

# 小贴士 & 常见坑

- RNG 与回放一致性非常重要（存 seed 或 RNG 状态）。
- GUI 动画不要把逻辑与渲染耦合（会导致卡顿与难测）。
- Expectimax 计算量随深度爆炸，注意对分支（随机 tile 出现）做概率剪枝或使用 heuristic rollouts。
- RL 训练容易不稳定，先做监督学习 warm-start 更容易收敛。
