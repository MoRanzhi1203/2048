# 使用 PyQt5 实现 2048 桌面版游戏：MVC 架构与撤销/重做

前两篇里，我们用纯 Python 完成了 **2048 的数学模型** 与 **带历史记录的控制台版本**。控制台版适合验证逻辑，但它的交互体验并不好：每走一步都要 `cls` 清屏、光标闪烁，而且只能靠键盘操作，鼠标完全派不上用场。

这一篇我们把游戏搬到桌面：用 **PyQt5** 实现图形界面，并在这个过程中做两件工程上更重要的事——

1. 用 **MVC 架构** 把"游戏逻辑"和"界面渲染"彻底解耦；
2. 基于状态快照栈实现 **撤销 / 重做**。

### 1. 为什么需要 MVC

在控制台版里，`_move`、`display_grid`、`get_key` 全都塞在同一个类里。一旦换成 GUI，如果继续这么写，就会出现典型问题：**逻辑和渲染耦合**——想测试一次合并是否正确，却不得不先创建一个窗口；想改一次配色，却要翻遍业务代码。

因此我们按 **MVC（Model–View–Controller）** 分层：

| 层 | 类 | 职责 |
| --- | --- | --- |
| **Model** | `GameCore` | 棋盘状态、合并规则、得分、历史持久化、撤销/重做（**不含任何界面代码**） |
| **View** | `TileLabel` / `BoardView` | 只负责把 Model 的网格渲染成方块，**不处理任何业务逻辑** |
| **Controller** | `MainWindow` | 捕获键盘/按钮事件，调用 Model，再通知 View 刷新 |

分层的直接好处：`GameCore` 不依赖 PyQt，可以像第 1、2 篇那样单独导入、单独测试；界面想换成 Tkinter、Web 或命令行，核心逻辑都无需改动。



### 2. Model：与原版无异的游戏核心

`GameCore` 承载了前两篇的全部逻辑：棋盘、随机方块、移动合并、胜负判断，并在第 2 篇的基础上继续做历史记录持久化。

#### 2.1 关键点

- **合并规则**：先压缩非零元素，再合并相邻相同值，最后右侧补零；
- **方向抽象**：上下先转置、左右按需翻转行，四个方向复用同一套逻辑；
- **历史持久化**：沿用第 2 篇的 `save_game_state` / `update_index`（`best_score.json`、`game_state.json`、`index.json` 同名同结构）；`record_move` 则按 GUI 版需要改写为「步数 / 操作类型 / 当前分数 / 网格状态」四列。

#### 2.2 代码实现（合并核心）

```python
def _merge_line(self, line):
    """
    合并单行（核心算法）：压缩非零 -> 相邻相同合并 -> 右侧补零。
    返回 (新行, 是否发生变化)。
    """
    original = list(line)
    compressed = [v for v in line if v != 0]

    merged = []
    i = 0
    while i < len(compressed):
        if i + 1 < len(compressed) and compressed[i] == compressed[i + 1]:
            merged.append(compressed[i] * 2)
            self.score += compressed[i] * 2
            i += 2          # 合并后一次跳过两个元素
        else:
            merged.append(compressed[i])
            i += 1

    merged += [0] * (self.grid_size - len(merged))
    return merged, merged != original
```

#### 2.3 方向抽象

四个方向不需要写四份逻辑，只要在"行"这一层做统一处理，其余靠转置与翻转复用：

```python
def _slide(self, direction):
    moved = False
    if direction in ('up', 'down'):
        self.grid = [list(row) for row in zip(*self.grid)]  # 转置

    for i in range(self.grid_size):
        row = self.grid[i][::-1] if direction in ('right', 'down') else self.grid[i]
        new_row, has_moved = self._merge_line(row)
        if direction in ('right', 'down'):
            new_row.reverse()
        self.grid[i] = new_row
        moved = moved or has_moved

    if direction in ('up', 'down'):
        self.grid = [list(row) for row in zip(*self.grid)]  # 还原
    return moved
```



### 3. View：用 QGridLayout + QLabel 绘制棋盘

PyQt 里绘制棋盘有两条常见路线：`QGraphicsView/QGraphicsScene`，或自定义 `QWidget` + `paintEvent`（`QPainter`）。本系列先选一个更简单、更易读的方案——**`QGridLayout` 布局 16 个 `QLabel`**。它足够表达静态棋盘，也为第 4 篇的动画改造留出了清晰边界。

#### 3.1 关键点

- **方块是"格子"**：每个 `TileLabel` 是一格，用固定尺寸的 `QLabel` + 样式表绘制圆角背景与文字；
- **颜色映射**：不同数值对应 2048 官方配色，空格用统一的底板色；
- **View 只渲染**：`BoardView.render(grid)` 接收一个二维网格，逐格刷新，不做任何判断。

#### 3.2 代码实现（方块渲染）

```python
class TileLabel(QLabel):
    """单个方块（View 的最小元素）"""

    # 经典 2048 配色（空格底色单独用 COLOR_EMPTY）
    COLORS = {
        2: (238, 228, 218), 4: (237, 224, 200),
        8: (242, 177, 121), 16: (245, 149, 99),
        32: (246, 124, 95), 64: (246, 94, 59),
        128: (237, 207, 114), 256: (237, 204, 97),
        512: (237, 200, 80), 1024: (237, 197, 63),
        2048: (237, 194, 46),
    }
    # 4096 起的深琥珀色阶：与 2048 拉开明度差，同时保证白字可读
    HIGH_COLORS = {
        4096: (237, 176, 32), 8192: (227, 159, 22), 16384: (214, 143, 15),
    }
    TEXT_DARK = "#776e65"
    TEXT_LIGHT = "#f9f6f2"

    def __init__(self, value=0, parent=None):
        super().__init__(parent)
        self.setAlignment(Qt.AlignCenter)
        self.setFixedSize(TILE_SIZE, TILE_SIZE)   # 固定尺寸，保证严格正方形
        self.set_value(value)

    def set_value(self, value):
        """根据数值刷新圆角背景、字色与字号"""
        if value == 0:
            bg = QColor(COLOR_EMPTY)
        elif value > 2048:
            bg = QColor(*self.HIGH_COLORS.get(value, (198, 128, 12)))
        else:
            bg = QColor(*self.COLORS.get(value, (60, 58, 50)))

        color = self.TEXT_DARK if value <= 4 else self.TEXT_LIGHT
        # 字号随位数自适应：2–64 常规 36px，逐级递减，保证大数值不溢出
        if value == 0:
            size = 1
        elif value < 100:
            size = 36
        elif value < 1000:
            size = 30
        elif value < 10000:
            size = 24
        else:
            size = 17

        self.setStyleSheet(
            f"QLabel {{ background-color: {bg.name()}; color: {color};"
            f" border-radius: {TILE_RADIUS}px; font-size: {size}px; font-weight: bold; }}")
        self.setText("" if value == 0 else str(value))
```

棋盘视图管理一个 4×4 的 `TileLabel` 矩阵：

```python
class BoardView(QWidget):
    def __init__(self, grid_size=4, parent=None):
        super().__init__(parent)
        self.grid_size = grid_size
        self.setAttribute(Qt.WA_StyledBackground, True)
        self.setStyleSheet(
            f"background-color: {COLOR_BOARD}; border-radius: {BOARD_RADIUS}px;")
        side = BOARD_PADDING * 2 + TILE_SIZE * grid_size + TILE_GAP * (grid_size - 1)
        self.setFixedSize(side, side)               # grid_size=4 时为 434 × 434

        layout = QGridLayout(self)
        layout.setSpacing(TILE_GAP)
        layout.setContentsMargins(BOARD_PADDING, BOARD_PADDING,
                                  BOARD_PADDING, BOARD_PADDING)

        self.tiles = []
        for i in range(grid_size):
            row = []
            for j in range(grid_size):
                tile = TileLabel()
                layout.addWidget(tile, i, j)
                row.append(tile)
            self.tiles.append(row)

    def render(self, grid):
        """按当前网格刷新所有方块"""
        for i in range(self.grid_size):
            for j in range(self.grid_size):
                self.tiles[i][j].set_value(grid[i][j])
```

> **小坑提醒**：用 `QPalette` 改背景既做不了圆角，还必须记得 `setAutoFillBackground(True)` 才生效；改用 `setStyleSheet` 设置 `background-color` + `border-radius` 更省事。方块用 `setFixedSize` 固定尺寸，是最稳妥地保证"16 格严格等大、棋盘正方形"的方式。

### 4. Controller：键盘事件与按钮

Controller 是 `MainWindow`。它在 `keyPressEvent` 里把按键翻译成"意图"，再驱动 Model、刷新 View。

#### 4.1 关键点

- **方向键 / WASD**：四个方向移动；
- **Ctrl+Z / Ctrl+Y**：撤销 / 重做；
- **在窗口层捕获按键**：比让某个子控件持有焦点更稳妥，不会出现"点了按钮之后方向键失效"。

#### 4.2 键盘事件

```python
def keyPressEvent(self, event):
    key = event.key()
    ctrl = bool(event.modifiers() & Qt.ControlModifier)

    if ctrl and key == Qt.Key_Z:
        self.on_undo()
        return
    if ctrl and key == Qt.Key_Y:
        self.on_redo()
        return

    direction = {
        Qt.Key_Up: 'up', Qt.Key_W: 'up',
        Qt.Key_Down: 'down', Qt.Key_S: 'down',
        Qt.Key_Left: 'left', Qt.Key_A: 'left',
        Qt.Key_Right: 'right', Qt.Key_D: 'right',
    }.get(key)

    if direction is None:
        super().keyPressEvent(event)
        return

    self.on_move(direction)
```

> **关键小坑**：`QPushButton` 默认可获取焦点。一旦某个按钮拿到焦点，**方向键会被 Qt 的焦点导航拦截**，根本传不到窗口的 `keyPressEvent`（现象就是"字母键 WASD 有效、方向键无效"）。解决办法是让按钮不抢焦点，并让主窗口自己持有焦点：
>
> ```python
> button.setFocusPolicy(Qt.NoFocus)   # 创建按钮时
> self.setFocusPolicy(Qt.StrongFocus) # 窗口本身
> ```

#### 4.3 状态刷新

移动、撤销、重做最终都收敛到"改 Model → 刷新 View"这一条链路：

```python
def on_move(self, direction):
    if self.model.game_over:
        return
    if not self.model.apply_move(direction):
        return

    self.refresh()
    if self.model.game_over:
        self.show_game_over()
    elif self.model.won and not self.win_announced:
        self.win_announced = True     # 只弹一次"恭喜胜利"
        self.show_game_won()

def _sync_history_buttons(self):
    """撤销/重做按钮的视觉状态只跟随历史栈（与第 4 版同名同职责）"""
    self.undo_button.setEnabled(self.model.can_undo())
    self.redo_button.setEnabled(self.model.can_redo())

def refresh(self):
    """把 Model 的最新状态同步到 View 与分数/按钮状态"""
    self.board_view.render(self.model.grid)
    self._render_score(self.score_label, "分数", self.model.score)
    self._render_score(self.best_label, "最高分", self.model.best_score)
    self._sync_history_buttons()
```

`refresh()` 是维持 MVC 一致性的关键：**任何一次状态变化，都只通过它来更新界面**，避免界面出现"一半新一半旧"的中间态。按钮的启用状态被单独抽成 `_sync_history_buttons()`——**只由历史栈决定**（第 4 版同名同职责，便于两版一致维护）。



### 5. 撤销 / 重做：基于状态快照栈

博客大纲里提到"用历史记录栈实现 undo/redo"。实现方式有很多：记录每一步的 `(动作, 随机种子)` 再回放，或直接保存**状态快照**。这里选择后者，简单且绝对可靠。

#### 5.1 关键点

- 每次**合法移动前**，先把当前 `(grid, score, game_over, won, current_move, history_count)` 深拷贝压入 `undo_stack`；
- `undo()`：弹出 `undo_stack` 顶部恢复到棋盘，同时把当前状态压入 `redo_stack`；
- `redo()`：反向操作；
- 发生新移动时清空 `redo_stack`（经典的"分支被覆盖"语义）。

#### 5.2 代码实现

```python
def apply_move(self, direction):
    """执行一次移动：记录快照 -> 合并 -> 写历史 -> 生成新方块 -> 判断胜负"""
    snapshot = self._snapshot()
    if not self._slide(direction):
        return False                     # 非法移动，不产生快照

    self.undo_stack.append(snapshot)
    self.redo_stack.clear()

    self._sync_best_score()              # 分数刷新纪录时同步最高分
    self.record_move(DIRECTION_NAMES[direction])
    self.add_new_tile()
    self.record_move("添加新方块")

    self.check_win()
    self.check_game_over()
    return True

def _snapshot(self):
    """当前状态快照（深拷贝，避免后续修改污染历史）"""
    return {
        "grid": deepcopy(self.grid),
        "score": self.score,
        "game_over": self.game_over,
        "won": self.won,
        "current_move": self.current_move,
        "history_count": self.history_count,   # 当前生效的历史行数，undo/redo 时据此回退 history.csv
    }

def undo(self):
    if not self.undo_stack:
        return False
    self.redo_stack.append(self._snapshot())
    self._restore(self.undo_stack.pop())
    self._sync_best_score()
    self.save_game_state()      # 撤销后同步持久化
    self.update_index()
    return True

def redo(self):
    if not self.redo_stack:
        return False
    self.undo_stack.append(self._snapshot())
    self._restore(self.redo_stack.pop())
    self._sync_best_score()
    self.save_game_state()
    self.update_index()
    return True
```

> **三个细节**：
> 1. `_snapshot` 必须用 `deepcopy`——棋盘是嵌套列表，浅拷贝会让撤销栈和当前棋盘共享同一块内存，结果"撤了个寂寞"。
> 2. **非法移动不生成快照**（`_slide` 返回 `False` 时直接 return），否则连按几次"撞墙"方向键会把有效历史挤掉。
> 3. 快照里额外保存 `current_move` 与 `history_count`：`_restore()` 会据此重写 `history.csv`，使撤销/重做后的历史文件与棋盘状态保持一致（撤销后再走新一步时，会丢弃被撤销掉的那些"未来行"）。



### 6. 与历史记录功能打通

#### 6.1 启动页设计

Model 完整保留了第 2 篇的持久化能力，所以 GUI 版天然支持"继续上一局"。为了不把它做成"一上来先弹一个确认框"，我们用一个 **启动页**（`QStackedWidget` 的第 0 页）来承载这个选择：

- `startup()` 读取 `index.json`：有未完成的对局就停在启动页（展示上一局的分数），否则直接进入游戏页；
- 启动页用「继续上一局」与「开始新游戏」两个按钮完成选择，取代「弹 `QMessageBox` 询问是否续玩」的做法（游戏结束 / 达成 2048 的提示仍使用 `QMessageBox`）；
- 每走一步写 `history.csv` 与 `game_state.json`，通过 `is_completed`（`game_over or won`）判断对局状态。

这样，第 2 篇积累的 `game_history/` 数据在 GUI 版里继续生长，为后续第 7 篇"用历史数据训练模型"准备样本。



### 7. 界面视觉规范与高 DPI 适配

MVC 跑通之后，我们对界面做了一轮**纯视觉**打磨——只改布局、配色、字号、圆角、间距与控件状态，**不动任何游戏逻辑、存档、分数计算与键盘规则**。

#### 7.1 把样式收敛成常量

颜色与尺寸集中定义在文件顶部，按钮 QSS 用 f-string 复用这些常量，避免到处散落硬编码：

TILE_RADIUS, BOARD_RADIUS = 6, 9
BOARD_SIDE = BOARD_PADDING * 2 + TILE_SIZE * 4 + TILE_GAP * 3   # 434

#### 7.2 两个页面的布局与尺寸

- **启动页**：`标题(70px) → 副标题(13px) → 摘要卡(330×110) → 主按钮(330×48) → 文字按钮(330×44)`，整体同轴居中；摘要卡内是「上一局 + 大数字 + 下方标签（分数 / 最高分）」。
- **游戏页**：标题 48px，两张 96×62 的统计卡与标题**顶边对齐**；棋盘恒为 434×434（`padding`/`gap` 各 10、格圆角 6、棋盘圆角 9）；底部「撤销 / 重做」居左、「新游戏」居右，三键统一 100×44，且左右边缘与棋盘对齐。

按钮按「主 / 次 / 文字」三套 QSS 拉开层级，每套都带 `hover / pressed / focus / disabled` 四态；`border` 恒为 2px（默认透明），这样状态切换时不会发生尺寸跳动。

#### 7.3 键盘可达：又踩了一次"方向键失效"

启动页的两个按钮需要键盘可达：`Tab` 聚焦、`回车 / 空格` 触发。这里再次撞上那个焦点坑——`QPushButton` 默认可获取焦点，**一旦按钮拿到焦点，方向键会被 Qt 的焦点导航拦截**，传不到窗口的 `keyPressEvent`。因此策略是：

- **启动页按钮**：可聚焦（`StrongFocus`），并额外支持回车触发；
- **游戏页按钮**：显式 `NoFocus`，保证游戏中的方向键始终直达窗口。

```css
/* 启动页按钮带可见 focus 态 */
QPushButton:focus { border-color: #8f7a66; }
```

```python
class EnterButton(QPushButton):
    """可聚焦按钮；额外支持回车触发（QPushButton 原生只响应空格）"""
    def keyPressEvent(self, event):
        if event.key() in (Qt.Key_Return, Qt.Key_Enter):
            self.click()
            event.accept()
            return
        super().keyPressEvent(event)
```

#### 7.4 高 DPI 适配

在创建 `QApplication` **之前**开启缩放，让逻辑像素随系统缩放整体放大，避免 125% / 150% 下的错位与截断：

```python
QApplication.setAttribute(Qt.AA_EnableHighDpiScaling, True)
QApplication.setAttribute(Qt.AA_UseHighDpiPixmaps, True)
```

随后用 `QT_SCALE_FACTOR` 在 100% / 125% / 150% 三档逐一断言：窗口尺寸不变形、棋盘保持正方形、控件不越界、文字不裁切。

- 启动页：继续上一局 / 开始新游戏（`Tab` 切换焦点，`回车` / `空格` 触发）。



### 9. 总结

这一篇把 2048 从控制台带到了桌面，重点不在"让方块好看"，而在三件工程实践：

1. **MVC 分层**：`GameCore`（Model）不依赖任何 UI，可独立测试；`BoardView`（View）只渲染；`MainWindow`（Controller）只做事件分发与状态同步。三层之间通过 `refresh()` 单向收敛。
2. **状态快照式撤销/重做**：`undo_stack` / `redo_stack` 保存 `deepcopy` 的状态快照，语义清晰、实现简单。
3. **界面规范化**：把颜色 / 尺寸 / 圆角收敛成常量，启动页与游戏页统一视觉，并补齐了高 DPI 适配与键盘焦点可达。

当前实现每次移动都是"整盘重绘"，动画是瞬移的。**下一篇**我们将针对性能与观感做优化：把棋盘拆成"静态背景层 + 动画层"，用定时器对每个方块的起止位置做插值，实现平滑的移动与合并动画。
